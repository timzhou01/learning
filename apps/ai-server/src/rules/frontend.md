# Frontend Rules

- Follow the existing frontend project structure and component conventions.
- Prefer reusing existing components, hooks, utilities, and styles.
- Keep UI state local unless shared state is clearly required.
- Avoid introducing new state-management libraries unless the project already uses them.
- Keep components focused and avoid unnecessary abstraction.
- Preserve existing loading, error, empty, and disabled states.
- Follow existing API request patterns instead of creating a parallel client.
- Keep accessibility and keyboard behavior consistent with existing components.
- Avoid unnecessary re-renders and premature optimization.
- Add or update tests when the existing frontend module has test coverage.
