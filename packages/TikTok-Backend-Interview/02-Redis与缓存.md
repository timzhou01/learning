## 02. Cache Aside 是什么？

**参考答案：** 读：先缓存、未命中读库并回填；写：先更新数据库再删除缓存；配合 TTL 和失败处理。

## 03. 为何更新数据库后删除 Redis？

**参考答案：** 数据库作为权威源，删除使下次读取重新填充；仍可能出现并发旧值回填，需要根据一致性要求补偿。

**参考答案：** 不存在的 ID 每次落到数据库；可缓存短 TTL 空值、布隆过滤器、参数校验和限流。

## 05. 缓存击穿是什么？

**参考答案：** 单个高热 Key 失效引发并发回源；互斥重建、单飞机制、逻辑过期和异步刷新。

## 06. 缓存雪崩是什么？

**参考答案：** 大量 Key 同时过期或 Redis 故障导致回源洪峰；随机 TTL、预热、限流降级、多副本高可用。

**参考答案：** 可预判热点或批量到期时，由 Job 提前加载；需注意预热成本、更新延迟和数据正确性。

## 08. Redis TTL 过期后一定立即删除吗？

**参考答案：** 不一定；通常结合惰性删除和定期过期扫描；不能把 TTL 当作实时通知机制。

## 13. 分布式锁续租有什么风险？

**参考答案：** 进程长时间停顿会错过续租，锁失效后旧持有者继续执行；需要业务幂等或 fencing token 等防护。

## 14. Redis 和 MySQL 如何保证最终一致？

**参考答案：** 数据库为准，缓存删除失败后有重试、TTL、监控；关键业务可用变更事件与版本校验，无法只靠 TTL 保证强一致。

## 15. Redis 的 RDB 和 AOF 有什么区别？

**参考答案：** RDB 是时间点快照，恢复通常快但可能丢失快照后更新；AOF 记录写命令，丢失窗口与刷盘策略有关。

## 16. Redis 主从和 Sentinel、Cluster 区别？

**参考答案：** 复制提供副本，Sentinel 负责故障发现/自动主从切换，Cluster 通过分槽实现数据分片与扩容。

**参考答案：** Pub/Sub 更偏在线推送、不保留离线消息；Stream 可持久化消息并支持消费组和确认。
